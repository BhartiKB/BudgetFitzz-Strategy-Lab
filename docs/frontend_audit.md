# Frontend audit — Version 10

## Current state (2026-07-17)

BudgetFitzz is a deliberately offline, static web application served by `app/server.py`. The live UI is a single HTML document (`app/index.html`) with one data-fetching script (`app/app.js`) and stylesheet layers (`app/styles.css`, `app/responsive.css`). It currently reads `app/data/dashboard.json`, which is generated by `insta_strategy_lab.reporting.builder.build_app_data` during the pipeline/finalisation workflow.

The existing build has strong evidence lineage: observed values, targets, and hypotheses remain distinct; local relative asset paths work in an offline package; and the data payload points to the raw, derived, and analysis artefacts. It also has meaningful coverage of the analytical report.

The principal product gaps are architectural rather than analytical: the browser consumes one broad dashboard payload, visual rules are concentrated in a minified CSS file, navigation is anchor-only, responsive behaviour is limited, and visual states such as loading, empty, error, and selected are not first-class. There was no prior Figma file, token system, Code Connect mapping, or reusable Figma component library to preserve.

## Source-of-truth contract

The pipeline remains the source of analytical truth. `build_app_data` will now emit both the existing compatibility payload and `app/data/platform_manifest.json`. The manifest is a presentation contract — it groups only pipeline-derived facts, evidence, plan, validation, assets, and agent trace summaries. It must never become a secondary analytics calculation layer.

| Concern | Authoritative source | Frontend use |
| --- | --- | --- |
| Baseline metrics and audit | `analysis/analysis_results.json` / processed CSV | KPI and performance cards |
| Metric definitions | `data/processed/metric_contract.json` | Internal contract only; formulas stay out of the UI |
| Diagnosis and strategy | Agent workflow outputs | Strategy and workflow views |
| Content plan | Validated seven-day plan | Content Studio cards (exactly five posts, two videos) |
| Video rationale | `analysis/video_generation_briefs.json` | Storyboard and caption/context alignment |
| Validation | `analysis/validation_report.json` | Validation console |
| Media | local `assets/` paths | Offline previews and videos |

## Frontend migration

1. Preserve the static/offline delivery model and relative assets.
2. Introduce semantic CSS tokens (`--bf-*`) matching the Figma foundations.
3. Replace the one-dimensional dashboard with product-level navigation: Overview, Content Studio, Performance, Strategy, Workflow, and Validation.
4. Render all product content from the generated manifest; no copied KPI values or fabricated performance figures may enter browser code.
5. Add accessible navigation, skip links, live loading/error states, responsive grids, and reduced-motion behaviour.
6. Keep machine-readable formulas in the manifest/metric contract and out of visual UI.

## Figma / frontend mapping

The Figma file is named **BudgetFitzz — Instagram Strategy Intelligence Platform**. Its intended token mapping is documented in `docs/figma_handoff.md` and `config/figma.json`; Figma variables use the same CSS custom-property syntax as the browser tokens. Figma creation must be treated as an external publish operation. The automatic visual capture was blocked by the environment because it would export the local dashboard to an external service, so no existing app data or media was exported by that capture step.

## Files in scope

- Modify: `app/index.html`, `app/app.js`, `app/styles.css`, `app/responsive.css`, `src/insta_strategy_lab/reporting/builder.py`, validation and frontend tests.
