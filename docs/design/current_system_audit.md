# Current system audit

## Verified architecture

The application is a dependency-light single-page frontend. `app/index.html`
defines the shell, `app/app.js` fetches `app/data/platform_manifest.json`, and
`app/styles.css`, `app/responsive.css`, and `app/tokens.css` define the visual
system. Browser navigation is hash-based and rendered from the manifest.

`app/server.py` is a route-allowlisted Python `ThreadingHTTPServer`. It serves
the app, assets, selected analysis files, packages, and the narrowly scoped
generation import/approval API. It does not expose arbitrary paths or secrets.

The manifest is generated by `src/insta_strategy_lab/reporting/builder.py` from
authoritative analysis, strategy, plan, workflow, validation, submission, and
generation output files. This is the single source of browser-visible values.

## Content generation

`ContentPlannerAgent` and `CreativeDirectorAgent` produce the seven planned
content items and caption-backed video briefs. The hybrid workflow stores exact
prompts and per-asset generation packages under `analysis/`. Manual imports are
quarantined, inspected, post-processed, given a version, and require explicit
approval. Existing assets stay active until approval; superseded versions are
preserved in `assets/versions/`.

## What remains untouched

- Metric calculations, outlier treatment, diagnosis, strategy, and plan shape.
- Five-post/two-video rule.
- Agent names, workflow memory, spend ledger, route allowlisting, and Render
  service configuration.

## UI areas changing

- A new manifest-driven Production route for the hybrid generation workflow.
